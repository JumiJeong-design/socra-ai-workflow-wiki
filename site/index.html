원칙 · 한 번 읽는다
핵심 관점원칙현장 이슈에서 AI가 맡을 일과 사람이 판단할 일을 먼저 가르고, 제품 단계별로 전략을 다르게 잡는다. 핵심 원칙원칙탐색은 빠른 도구에서 하고, 확정 기준은 팀이 다시 찾을 수 있는 표면에 남긴다. 완료 기준 3단계 NEW원칙1차 / 공유 가능 / 픽스. 에이전트의 "완료"와 디자이너의 "완료"를 가르고, 일정은 두 날짜로 말한다. AI 도입 시 일정 산정 가이드원칙처음 2~4주는 학습 곡선을 감안하고, 어떤 업무가 실제로 단축되는지 기준을 잡는다. 개발 협업 용어원칙디자이너가 FE와 이야기할 때 자주 어긋나는 용어를 같은 뜻으로 맞춘다.
절차 · 세팅
빠른 시작세팅25분. docs 폴더, product-context, agent-rules, 진입점 연결까지 최소 구성으로 시작한다. AI 에디터 연결 설정세팅MCP를 지원하는 도구에서 진입 파일과 규칙 문서를 연결한다. Figma MCP 연결 설정세팅Remote/Desktop 차이, 계정 권한, Dev Mode, 첫 읽기 테스트까지 연결 전에 확인한다.
절차 · 프로세스 구축
문서 목적과 레이어 구조프로세스 구축무엇을 어디에 적을지 정하고, 문서마다 역할 번호를 붙여 현재 기준·규칙·절차·기록을 가른다. 구축 우선순위와 MVP 문서 4개프로세스 구축product-context, ux-principles, component-usage, review-checklist부터 만든다. 문서 구축 가이드 0~8프로세스 구축디자인 탐색 구체화부터 Release / Operation까지 문서 아홉 개를 순서대로 세운다. 2주 실험 계획프로세스 구축실험 기록으로 과정, 효과, 리스크, 다음 룰을 남긴다. Daily Worklog → Wiki프로세스 구축날짜별 기록에서 검증된 패턴만 위키로 올린다. 에이전트 핸드오프프로세스 구축세션이 바뀌어도 다음 에이전트가 같은 자리에서 시작하게 한다. 전달의 완결 형태는 네 칸.
절차 · 제품 구축
화면 디자인제품 구축새 화면을 디자인 시스템 인스턴스로 그리고 정합까지 가는 순서. 디자인 구축·전달 워크플로제품 구축Figma 의도 → Git Draft PR → 같은 브랜치의 Storybook 프리뷰로 도는 구축단계 파일럿. Figma-Git Sync제품 구축피그마와 깃 중 무엇이 정본인지 경계를 긋는다. AI 모션 제작 워크플로제품 구축레퍼런스 녹화, 조정 가능한 미리보기, CSS 코드와 FE 전달 패키지까지. 제품 유형별 확장제품 구축다크모드, 다국어, 반응형, 모션, 브랜드 중 내 제품에 필요한 것을 네 질문으로 고른다.
절차 · 제품 운영
컴포넌트 업데이트제품 운영디자이너와 개발자가 같은 컴포넌트를 고칠 때의 순서와 공동 수정 규칙. Storybook QA 하네스제품 운영Theme, Viewport, Locale, Long Content, Empty/Error/Fallback을 반복 검증축으로 둔다. AI 디자인 리뷰제품 운영AI에게 리뷰를 맡길 때의 기준과 사람이 남겨야 하는 판단. 대량 작업·재발 방지제품 운영감사 → 승인 → 실행, 파일럿 1건 → 배치, 그리고 같은 실수를 끊는 재발 방지 규칙. 실제 업무 활용제품 운영신규 화면, 기존 화면 개선, 개발 핸드오프에 어떤 문서와 체크리스트를 붙일지.
