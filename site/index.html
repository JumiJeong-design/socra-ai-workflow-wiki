프로덕트 디자이너를 위한 AI 워크플로우 위키

AI와 함께 제품을 설계하고 구현하면서 반복 가능한 협업 방식과 시행착오를 정제해서 쌓는다. 한 번 읽는 원칙, 하면서 따라가는 절차, 막혔을 때 찾아보는 함정 세 묶음이다.

읽기 경로
처음 세팅하는 디자이너 5단계
  1. 빠른 시작
  2. AI 에디터 연결 설정
  3. Figma MCP 연결 설정
  4. 무엇을 갖추고 시작하나
  5. 하네스
화면 하나를 끝까지 5단계

  2. 채널 다섯과 게시 게이트
  3. DS → 스토리북 계약 정리
  4. 완료 기준 3단계
  5. 화면 → DS → 화면 왕복

  3. 세션 시작 · 병렬 · 복구 · 마무리

표면
원칙 · 한 번 읽는다
핵심 관점원칙현장 이슈에서 AI가 맡을 일과 사람이 판단할 일을 먼저 가르고, 제품 단계별로 전략을 다르게 잡는다. 핵심 원칙원칙탐색은 빠른 도구에서 하고, 확정 기준은 팀이 다시 찾을 수 있는 표면에 남긴다. 운영 루프 시각화원칙탐색 → 확정 기준 → 제품 반영 → QA → 기록·보강으로 도는 출시 후 운영 루프를 한 장으로 본다. 완료 기준 3단계원칙1차 / 공유 가능 / 픽스. 에이전트의 "완료"와 디자이너의 "완료"를 가르고, 일정은 두 날짜로 말한다. AI 도입 시 일정 산정 가이드원칙처음 2~4주는 학습 곡선을 감안하고, 어떤 업무가 실제로 단축되는지 기준을 잡는다. 개발 협업 용어원칙디자이너가 FE와 이야기할 때 자주 어긋나는 용어를 같은 뜻으로 맞춘다.
절차 · 세팅
빠른 시작세팅10분. 진입 파일, 정본 순서, 워크로그 자리만 만들고 첫 작업을 맡긴다. AI 에디터 연결 설정세팅MCP를 지원하는 도구에서 진입 파일과 규칙 문서를 연결한다. Figma MCP 연결 설정세팅Remote/Desktop 차이, 계정 권한, Dev Mode, 첫 읽기 테스트까지 연결 전에 확인한다.
절차 · 프로세스 구축
탐색 단계에서 기준 찾기프로세스 구축방향이 정해지기 전에는 루프를 돌리지 않는다. 반복되는 패턴에서 기준 후보를 뽑는다. 무엇을 갖추고 시작하나프로세스 구축기준 문서를 먼저 다 쓰지 않는다. 자리와 정본 순서만 정하고 루프를 돌리며 채운다. 기록을 위키로 올리기프로세스 구축날짜별 기록에서 경험 기록과 매뉴얼을 거쳐, 검증된 것만 공개 위키로 내린다.
절차 · 제품 구축
화면 디자인제품 구축새 화면을 디자인 시스템 인스턴스로 그리고 정합까지 가는 순서. Figma-Git Sync제품 구축피그마와 깃 중 무엇이 정본인지 경계를 긋는다. AI 모션 제작 워크플로제품 구축레퍼런스 녹화, 조정 가능한 미리보기, CSS 코드와 FE 전달 패키지까지. 제품 유형별 확장제품 구축다크모드, 다국어, 반응형, 모션, 브랜드 중 내 제품에 필요한 것을 네 질문으로 고른다.
절차 · 제품 운영
AI 디자인 리뷰제품 운영AI에게 리뷰를 맡길 때의 기준과 사람이 남겨야 하는 판단. 대량 작업·재발 방지제품 운영감사 → 승인 → 실행, 파일럿 1건 → 배치, 그리고 같은 실수를 끊는 재발 방지 규칙. 실제 업무 활용제품 운영신규 화면, 기존 화면 개선, 개발 핸드오프에 어떤 문서와 체크리스트를 붙일지.
막혔을 때 · 찾아본다
Figma MCP 작업 함정 모음Figma컴포넌트, API, 운영, 환경, 인스턴스·게시 정합 함정 14개. "값이 안 바뀐다", "0건이 나왔다"일 때 연다. 방향 이탈 감지에이전트피드백이 반복되거나 구현이 의도에서 멀어질 때 점검할 신호와 대응. 도구 / 작업 선택 가이드에이전트탐색, 정리, 검증, 전달 중 지금 일이 어디에 가까운지 판단하고 다음 행동을 고른다. 안 바뀌는 건 게시 때문이 아니었다 NEW사례「게시가 필요합니다」인데 게시할 게 없을 때. 안 바뀌는 원인 넷을 가른다. 규칙이 있는데 같은 실수가 난다 NEW사례규칙을 늘리지 말고 증상 색인과 실행 직전 훅으로 옮긴다. 0건과 결함 3곳 NEW사례전수 검사가 0을 내거나 일부러 둔 값을 결함으로 읽을 때 되묻는 법. 스토리북이 그림판이 될 때 NEW사례화면 스토리가 패키지 컴포넌트를 안 쓰고 손 마크업과 자리표시로 그려질 때. 게시본 두 개 직접 대조 NEW사례시각 비교 도구가 막혔을 때 URL 둘로 대조하고, 0%와 개수 비교를 믿지 않는다. 이름은 같은데 값이 다를 때 NEW사례토큰을 이름이 아니라 값으로, 라이트·다크 둘 다 대조한다. 문구의 정본이 세 군데일 때 NEW사례언어 모드를 걸고 재고, 정본은 기획이 정하게 한다.
AX 매뉴얼 · 처음부터 순서대로
읽는 순서지도구축 → 운영 → 원리. 처음이면 구축부터, 구조가 있으면 운영에서 자기 영역만, 설득해야 하면 원리부터. 구축 10~13구축전제 다섯 자리, 채널 다섯과 게시 게이트, 시각 기준, 행동 기준. 에이전트가 움직일 구조를 세운다. 운영 20~26운영사고마다 붙은 하네스 여섯, 그리고 DS 감사·화면 왕복·계약 정리·배포·세션·판단에 실제로 붙여 넣는 프롬프트. 원리 31~33원리이 방식의 단점 다섯, AI 몫과 사람 몫, PO·기획·FE·브랜드 사이의 중간안.
