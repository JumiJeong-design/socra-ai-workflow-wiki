# 사례: 시각 비교 도구가 막혔을 때 게시본 두 개를 직접 대조했다

> 구분: 사례 · 기간: 2026-09-05 ~ 09-21 · 관련: [매뉴얼 11장 스토리북의 장점](../manual/11-five-channels-publish-gate.md)

배포 전에 화면이 무엇이 바뀌는지 보고 싶은데, 시각 스냅샷 비교 도구가 요금제 한도 같은 이유로 막힌 경우의 사례다. 게시본 URL은 둘 다 있었다. 같은 스토리를 두 빌드에서 열어 픽셀을 비교하면 됐고, 실제로 됐다. 다만 처음 잰 수치는 전부 버렸다.

## 한눈에

| 날짜 | 무슨 일 | 뒤집힌 것 | 그래서 |
|---|---|---|---|
| 9/5 | 도구가 막혀 게시본 두 개를 직접 대조 | 처음 수치는 로딩 화면끼리 비교한 것. 36% 차이가 전부 무효 | 기준점은 렌더 완료 |
| 9/5 | 재측에서 네 컷이 0% | 0%도 못 믿는다. 볼 것이 그 자리에 없었다 | 잉크 비율을 같이 잰다 |
| 9/7 | 사이드바 폭 변경의 시각 QA | 바뀐 픽셀이 전부 폭 140 안, 사이드바 폭과 같았다 | 기준선을 따로 빌드해 맞대는 방법이 굳었다 |
| 9/12 | 도구가 「변경 1건」이라고만 함 | 656 대 656인데 하나 들어오고 하나 빠짐 | 수만 세면 「차이 없음」으로 잘못 읽는다 |
| 9/21 | 도구가 또 막힘 | 값을 덮어썼는데 화면이 그대로. 읽는 곳이 없었다 | 소비처부터 센다 |

## 원인과 처방

| 원인 | 처방 |
|---|---|
| 로딩 완료를 렌더 완료로 착각했다. `load` 시점에 스토리북은 아직 스피너를 그린다 | 기준점은 렌더 완료. 로딩 요소가 사라졌는지 따로 기다린다 |
| 0%는 「같다」가 아니라 「볼 것이 없다」일 수 있다 | 잉크 비율을 같이 잰다. 둘 다 0이면 결과가 아니라 오류로 보고 멈춘다 |
| 어느 빌드를 재는지 확인하지 않았다. 포트가 점유되면 옆 빌드를 잰다 | 서버가 주는 화면 목록으로 어느 빌드인지 확인해 표 위에 적는다. 점유한 프로세스는 죽이지 말고 포트를 옮긴다 |
| 개수만 비교하면 들어오고 나간 것이 상쇄된다 | 화면 목록 차집합을 양방향으로 낸다 |
| 덮어쓴 값을 화면이 읽는지 확인하지 않았다 | 전후 컷을 만들기 전에 소비처를 센다 |

한글 텍스트로 요소를 찾으면 유니코드 정규화 차이로 실패한다. 텍스트 말고 구조로 찾는다.

## 직접 해 보려면

```text
[게시본 URL A]와 [게시본 URL B]에서 같은 스토리 [스토리 ID 또는 목록]을 열어 픽셀 차이를 재 줘. 조건 넷.
1. load 이벤트 말고 렌더가 끝난 뒤(로딩 요소가 사라진 뒤)에 찍어.
2. 차이 %와 함께 잉크 비율(밝기 225 미만 픽셀 비율)을 같이 내. 둘 다 0이면 결과가 아니라 오류로 보고 멈춰.
3. 어느 빌드를 재고 있는지 서버가 주는 화면 목록으로 확인해서 표 위에 적어.
4. 결과 표는 스토리 / 차이 % / 잉크 A / 잉크 B / 차이 영역 좌표 다섯 칸으로.
```

```text
[게시본 URL A]와 [게시본 URL B]의 화면 목록을 각각 뽑아 차집합을 양방향으로 내 줘. A에만 있는 것, B에만 있는 것.
전체 개수가 같아도 차집합이 비어 있지 않을 수 있으니 개수로 판정하지 마. 각 항목이 어느 커밋에서 들어왔는지도 적어.
```

```text
[값 이름]을 바꾼 전후 비교 컷을 만들어 줘. 그 전에 그 값을 실제로 읽는 화면 규칙이 몇 개인지 먼저 세서 알려 줘.
읽는 곳이 0이면 컷을 만들지 말고 「이 값은 화면에 안 그려진다」고 보고해.
```
