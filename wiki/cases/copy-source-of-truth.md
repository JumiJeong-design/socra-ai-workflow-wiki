# 사례: 일본어 문구의 정본이 세 군데였다

> 구분: 사례 · 기간: 2026-09-02 ~ 09-23 · 관련: [매뉴얼 26장 판단을 올릴 때](../manual/26-prompt-judgement.md), [33장 중간안](../manual/33-principle-middle-ground.md)

출시 언어가 한국어가 아닌 제품에서, 피그마 화면 문구가 맞는지 AI에게 검수시키는 경우의 사례다. 일본 출시가 확정이고 한국어는 개발 편의였다. JP 문구를 검수하려고 화면을 열었더니 같은 문구가 화면 텍스트, 피그마 변수, 기획 시트 세 군데에서 서로 달랐다. 어느 것이 맞는지 디자인이 정할 수 없는데, 화면은 그중 하나를 이미 보여 주고 있었다.

## 한눈에

| 날짜 | 무슨 일 | 뒤집힌 것 | 그래서 |
|---|---|---|---|
| 9/2 | AI가 「JP 넘침 0건」 | 한국어로 잰 것이었다. 언어를 걸고 재니 다섯이 넘쳤다 | 언어 모드를 걸고 화면으로 잰다 |
| 9/2~8 | 언어 컬렉션이 일곱 | 잔재 셋에 물린 120곳을 되묶어 0으로. 넷은 구조라 판단으로 | 디자인 문구 변수는 디자인 시스템에만 |
| 9/2~8 | 문구 신설·정정 제안이 쌓였다 | 정본은 디자인이 정하지 않는다 | 다르다는 사실과 수치만 보여 준다 |
| 9/10 | 「기획서에 없어 잠정」으로 열어 둔 항목 | 무엇이 되면 닫히는지가 없었다. 반대로 「회신 대기」 항목은 정본이 이미 있었다 | 없는 것은 조건을 적고, 있는 것은 찾아서 닫는다 |
| 9/17~21 | AI가 문구 차이를 계속 올렸다 | 피그마 문구는 더미다. 디자인이 볼 것은 화면에서 깨지는지 | 선을 그었다 |
| 9/22~23 | 기획이 번역 시트를 줬다 | 정본이 시트 하나로 모였다 | 세 군데였던 정본이 한 곳으로 |

## 원인과 처방

| 원인 | 처방 |
|---|---|
| 피그마가 돌려주는 텍스트는 모드 해석 전 값이다. 언어 모드를 걸지 않으면 기본 언어를 잰다 | 출시 언어가 기본 언어가 아니면 감사 전에 페이지에 언어 모드를 걸고 화면으로 잰다 |
| 언어 컬렉션이 여러 벌 살아 있으면 어느 것을 갈아도 화면 일부만 바뀐다 | 디자인 문구 변수는 디자인 시스템에만. 제품 파일에 로컬 문구 컬렉션을 만들지 않는다 |
| 문구의 정본이 디자인 밖에 있는데 화면은 그중 하나를 이미 보여 준다 | 디자인은 다르다는 사실과 수치만 보여 준다. 어느 것이 정본인지는 기획이 정한다 |
| 「기획서에 없다」에서 멈추면 항목이 안 닫힌다 | 진짜 없는 것은 「무엇이 되면 닫히나」를 적고, 다른 곳에 이미 있는 것은 찾아서 닫는다. 후자가 더 많았다 |
| AI가 문구 자체를 검사 대상으로 삼는다 | 정본이 정해진 뒤 디자인이 볼 것은 하나다. 화면에 들어갔을 때 깨지지 않는가 |

## 직접 해 보려면

```text
[페이지 이름]의 [언어] 문구 넘침을 검사해 줘. 조건 둘.
1. 페이지에 [언어] 모드를 걸고 화면을 그린 뒤에 폭을 재. 저장된 텍스트 값으로 판정하면 기본 언어로 잰 게 돼.
2. 「0건」이 나오면 어느 언어 모드로 어디를 봤는지 같은 줄에 적어.
```

```text
문구 변수는 [담당 팀]이 관리해. 신설·정정을 제안하지 마.
화면 텍스트, 변수 값, [정본 문서]가 서로 다르면 어디가 어떻게 다른지 수치만 표로 보여 줘. 어느 쪽이 맞는지는 내가 [담당 팀]에 물을 거야.
```

```text
[문서 경로]에서 「기획서에 없음」「회신 대기」「잠정」으로 열려 있는 항목을 전부 모아 줘.
항목마다 ① 프론트 저장소·기획서·디자인 시스템에 이미 답이 있는지 찾아보고, 있으면 그 자리를 적어서 닫아.
② 진짜 없는 것만 남기고, 「무엇이 어떻게 되면 닫히는지」를 같은 줄에 적어.
```

```text
[전달할 내용]을 개발에 보내기 전에, [기획서 경로]에서 같은 내용이 이미 적혀 있는지 검색해 줘.
있으면 그 절 번호를 알려 주고 보내지 마. 정본이 둘이 돼. 없는 것만 남겨서 보낼 문장으로 다듬어.
```
