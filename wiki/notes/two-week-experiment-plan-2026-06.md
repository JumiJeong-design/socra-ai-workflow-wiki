# 2주 실험 실행 계획 (2026-06)

> 2026-10-08 v0.34에서 위키 「프로세스 구축」 묶음을 걷어 내면서 공개 사이트에서 내리고 기록으로 옮겼다. 6월 실험을 시작할 때 쓴 계획이고, 지금 따라 할 절차는 AX 매뉴얼이다.

AI Workflow 도입의 효과를 확인하기 위한 2주간 실험 계획이다. 결과물이 아니라 과정이 보이는 자료를 남기는 것이 핵심이다.

메인 담당자: 프로덕트 디자인팀 담당자가 진행 방식 논의, 회의 주체, 공유, 업무 팔로업을 맡는다. 파트원이 여럿이면 따로 정한다.

## 실험 12단계

1. **현재 디자인 업무에서 부담이 큰 지점 정리.** 기획서 확인, 화면 설계, 시안 제작, 핸드오프, QA 과정을 나열하고 손이 많이 가는 구간을 정리한다. (디자이너, PM/PO, FE)
2. **AI로 해결 가능한 업무와 불가능한 업무 구분.** 화면 초안 생성, 반복 UI 제작 대 브랜드 판단, UX 의사결정, 정책 해석. (디자이너, PM/PO)
3. **실험할 화면 또는 기능 선정.** 신규 기능 초기 화면, 반복 카드 UI, 빈 상태와 에러 상태처럼 효과를 확인하기 좋은 화면 1~2개. B2C 첫인상 구간은 AI 결과물을 그대로 쓰지 않고 디자이너가 강하게 보정한다. (디자이너, PM/PO)
4. **브랜드, UX, 디자인 시스템 기준 먼저 정의.** 톤앤매너, 컴포넌트 사용 기준, 컬러, 타이포, spacing, 피해야 할 느낌. (디자이너)
5. **기획서를 바탕으로 1차 화면 구조 생성 요청.** 화면 구조, 정보 우선순위, 주요 섹션, 상태값, 예외 케이스 초안. 완성된 디자인보다 구조화에 초점. (디자이너)
6. **화면 초안 또는 UI 변형안 생성.** 반복 UI, 상태 화면, 리스트·카드·폼 구조에 적극 활용. (디자이너, FE)
7. **디자이너 1차 보정.** 정보 구조, 시선 흐름, 문구, 간격, 브랜드 톤. 디자인 시스템 기준을 벗어난 결과물은 수정하거나 다시 만든다. (디자이너)
8. **프론트와 구현 가능성 검토.** 컴포넌트 구조, 상태 관리, 반응형, API 연동. (FE, 디자이너)
9. **핸드오프 항목 체크리스트화.** 컴포넌트, 상태값, 반응형, 에러·로딩·빈 상태, 문구, 접근성, API 필요 여부를 AI가 초안 작성하고 디자이너와 FE가 보완한다. (디자이너, FE)
10. **실제 구현 화면 기준으로 디자인 QA.** 피그마 시안이 아니라 실제 화면에서 간격, 정렬, 반응형, 문구, 상태, 브랜드 톤을 확인한다. (디자이너, PM/PO, FE)
11. **작업 시간과 품질 변화 기록.** 초안 제작 시간, 핸드오프 작성 시간, QA 수정 횟수, 브랜드 보정 시간, FE 커뮤니케이션 횟수. (메인 담당자, 디자이너)
12. **2주 후 결과 공유와 적용 기준 정리.** 계속 쓸 업무, 제한적으로 쓸 업무, 안 쓰는 게 나은 업무를 나눈다. (전체)

## 공유할 때 넣을 것

- 과정: 풀려던 문제, 적용한 화면과 기능, 쓴 도구, AI가 잘한 부분, 디자이너가 보정한 부분
- 결과: 협업 이슈, 실제로 줄어든 업무, 새로 생긴 리스크, 다시 쓸 프롬프트와 체크리스트, 팀에 적용하려면 필요한 룰

## 확인하고 싶었던 질문

- AI가 화면 초안 제작 부담을 실제로 줄여 주는가?
- 개발 핸드오프 준비에도 도움이 되는가?
- 디자인 QA의 반복 검수 부담을 줄일 수 있는가?
- B2C 브랜드 품질을 해치지 않으면서 쓸 수 있는가?
- 어떤 업무는 맡기고 어떤 업무는 디자이너가 직접 해야 하는가?
- 피그마, 코드, 문서는 각각 어느 단계에서 쓰는 것이 맞는가?
- AI 결과물을 디자인 시스템 룰 안에서 안정적으로 통제할 수 있는가?

기록은 사내 노션 DB 「디자인팀 AI 활용 실험 기록」에 라이트, 매뉴얼, AX 도입 테스트 세 템플릿으로 남겼다.
