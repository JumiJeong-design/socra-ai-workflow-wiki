# [21] 프롬프트 1. DS 토큰 정합 검토

> 구분: 운영 · 영역: 프론트

## 언제 쓰나

디자인 시스템 파일 안에서 컴포넌트를 전수하며 변수나 스타일이 안 물린 색, 텍스트 스타일, 라운드, 두께를 잡을 때.

## 이렇게 시킨다

프롬프트는 한 번에 붙여 넣습니다. 문단 하나가 지시 하나입니다.

| 문단 | 무엇을 정하나 |
| --- | --- |
| 1 | 범위: 볼 페이지와 뺄 페이지 |
| 2 | 셀 기준: 마스터만 센다 |
| 3 | 무엇을 결함으로 보나 |
| 4 | 텍스트는 글꼴 변수까지 본다 |
| 5 | 결과 형식: 표와 스캔 방법 한 줄 |
| 6 | 먼저 대조군으로 판정식을 검산한다 |
| 7 | 정본: 문서보다 피그마 |

```text
디자인 시스템 내부에 토큰이 잘 정합되어 있는지 검토해줘. 범위는 DS 파일의 Components · Foundation · Icons 세 페이지야. 가이드라인·링크/참고 페이지와 Components 안의 참고용·예외·기기 프레임·내부용(계약 없음) 섹션은 빼고, 뺀 항목과 개수를 수치 옆에 적어줘.

컴포넌트를 전수하면서 변수나 스타일이 미바인딩된 색, 텍스트 스타일, 라운드, 두께 하드코딩 케이스를 찾아줘. 마스터 기준으로만 세고, INSTANCE 노드와 아이콘 내부는 따로 갈라서 개수만 적어줘.

색과 텍스트 스타일 미바인딩은 전부 결함으로 세줘. 라운드·두께·간격은 「나중에 따로 움직일 자리」만 골라서 보고해줘. 이름이 곧 값인 size/N 바인딩은 목록에서 빼도 돼.

텍스트는 스타일이 붙었는지만 보지 말고 boundVariables의 fontFamily·fontSize가 살아 있는지까지 봐줘.

결과는 표로 줘. 노드 id · 소유 마스터 · 속성 · 현재값 · 후보 토큰 · 조상에 INSTANCE 있는지 · 오탐이면 사유. 표 위에 스캔 방법을 한 줄로 적어줘. skipInvisibleInstanceChildren 값, fills를 압축 인덱스로 읽었는지, strokeWeight를 네 변 키까지 봤는지.

미바인딩 목록을 내기 전에, 바인딩된 걸 확실히 아는 노드 몇 개를 대조군으로 넣어서 판정식이 그걸 「바인딩됨」으로 잡는지 먼저 보여줘. 전부 0이거나 전부 같은 값이면 코드 오류로 보고 멈춰줘.

정합 판정은 피그마 변수와 마스터를 직접 재서 해줘. 레포 문서와 다르면 문서 쪽이 낡은 것으로 보고 그 줄도 같이 적어줘.
```

## 왜 이 문장인가

- **범위와 뺄 것을 프롬프트에 박았습니다.** 「전체」를 에이전트가 정하게 두면 빼먹습니다. 범위를 잘못 잡아 78건을 통째로 빠뜨린 사고가 있었습니다.
- **대조군을 먼저 보여 달라고 합니다.** 바인딩 정보가 페인트 인덱스가 아니라 압축 인덱스로 들어와서, 판정 코드가 틀리면 전수가 「미바인딩」으로 나옵니다. 감사 결과가 전부 0이거나 전부 같으면 결과가 아니라 코드를 의심합니다.
- **마스터만 세고 인스턴스는 가릅니다.** 인스턴스를 같이 세면 같은 결함이 수백 번 세어집니다. 원인은 마스터 한 곳입니다.
- **이름이 곧 값인 토큰은 빼도 됩니다.** 토큰 이름은 따로 움직일 것에만 붙인다는 [구축 2 · 시각 기준](#manual-12)의 규칙과 같습니다.
- **레포 문서보다 마스터가 정본입니다.** 마스터 description에 「왜 바꿨는지」가 있고, 레포 문서는 마스터보다 낡습니다.

## 결과를 이렇게 확인한다

- 표 위의 스캔 방법 한 줄이 있나. 없으면 수치를 믿지 않습니다.
- 대조군이 「바인딩됨」으로 잡혔나.
- 미바인딩 목록에서 다섯 개만 찍어 피그마에서 열어 봅니다. 표본이 맞으면 넘어갑니다.

## 처음 보면 막히는 말

- **미바인딩:** 색이나 크기가 변수·스타일에 연결되지 않고 숫자로 직접 들어가 있는 상태.
- **마스터 / INSTANCE:** 마스터는 컴포넌트 원본, INSTANCE는 화면에 놓인 사본입니다. 사본의 결함은 원본을 고치면 같이 풀립니다.
- **size/N:** `size/16`처럼 이름이 값 그대로인 토큰. 따로 움직일 일이 없어서 감사 목록에서 뺍니다.
- **boundVariables:** 피그마가 「이 속성은 이 변수에 연결됨」을 적어 두는 칸. 스타일이 붙어 있어도 이 칸이 비면 연결이 끊긴 것입니다.
- **skipInvisibleInstanceChildren:** 숨겨진 사본 내부를 건너뛸지 정하는 피그마 설정. 켜고 끄는 데 따라 수치가 달라지니 어느 쪽으로 셌는지 적게 합니다.
- **압축 인덱스:** 칠(fill)이 여러 개일 때 피그마가 연결 정보를 칠 순서와 다른 번호로 돌려주는 방식. 판정 코드가 이걸 모르면 전부 「미바인딩」으로 나옵니다.
- **대조군:** 답을 이미 아는 노드. 판정식이 이걸 맞히는지 먼저 봐야 나머지 결과를 믿을 수 있습니다.
