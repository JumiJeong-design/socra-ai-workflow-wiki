# [20] 운영 0. 하네스

> 구분: 운영 · 영역: 공통

## 무엇을 돌리나

세션이 굴러가게 하는 장치다. 영역과 무관하게 공통이다. 구축 편이 기준을 세운다면 하네스는 그 기준이 매일 지켜지게 만드는 장치다. 여섯이다.

1. **워크로그.** 날짜별 파일 하나. 세션이 시작하면 오늘 것을 먼저 읽고, 끝날 때 무엇을 했고 무엇이 남았는지를 적는다. 계획과 기록이 같은 파일에 있다. 워크로그가 없으면 다음 세션은 어제를 모른다.
2. **plan 문서와 번호 스크립트.** 진행 중인 일은 레포의 plan 폴더가 정본이다. plan마다 첫 줄에 상태를 적는다. 새 plan은 스크립트로 만든다. 번호를 손으로 고르면 겹친다. 옆 창이 만들어만 두고 커밋 안 한 파일은 git 이력에 없기 때문이다. 스크립트는 원격 브랜치, 모든 워크트리, 미커밋 파일까지 훑는다.
3. **워크트리 격리.** 커밋할 일이 있는 세션은 시작 때 작업 폴더를 따로 만든다. 세션 여럿이 한 폴더를 쓰면 커밋 소유가 흐려진다. 충돌 보고를 받으면 이미 늦다.
4. **훅 셋.** 세션 시작 때 브리핑을 첫 화면에 얹는 훅(공유 폴더인지, 원격 브랜치보다 얼마나 뒤졌는지, 열린 체크박스가 몇 개인지, 오늘 워크로그가 있는지). 공유 폴더에서 위험한 git 명령을 실행 직전에 막는 훅. 「0건」 결과가 나오면 「범위를 적었나」를 상기시키는 훅. 커밋 직전에 문서 형식과 체인지셋을 검사하는 훅. 규칙으로 적어 두는 것만으로는 안 지켜져서 훅으로 옮겼다.
5. **메모리.** 사실 하나에 파일 하나. 사용자가 누구인가, 어떻게 일하라고 했는가, 무슨 결정이 있었는가, 어디를 보면 되는가. 색인 한 장이 세션마다 읽힌다. 레포에 이미 있는 것은 적지 않는다.
6. **토큰 절약.** 어디서 새는지 먼저 재고 도구를 붙인다. 재 보니 셸 출력이 3할이었고, 그 뒤에 압축 도구를 넣었다.

## 왜 이 자리가 필요한가

에이전트는 세션마다 초기화된다. 어제 무엇을 했는지, 어느 브랜치에 있는지, 옆 세션이 무엇을 고치고 있는지 모른다. 사람이 매번 말해 주면 되지만 그러면 사람이 하네스가 된다. 장치로 옮기면 사람은 판단만 하면 된다.

## 이렇게 된 이야기

하네스는 한 번에 설계된 게 아니라 사고마다 하나씩 붙었다. 순서대로 적는다.

- **6월, 워크로그.** 실험 첫 주부터 날짜별로 썼다.
- **7월 13일, 단일 에이전트로.** 두 종류의 에이전트를 병행하다 하나로 줄였다. 병렬이 필요하면 별도 구독이 아니라 서브에이전트와 워크트리로 간다. 팬아웃은 서너 개가 기본이다. 열 개를 띄웠다가 세션 한도에 걸린 날이 근거다.
- **8월 11일, 공유 폴더 사고.** `git add -A`로 옆 세션의 미커밋 작업이 내 커밋에 딸려 갔다. 규칙이 생겼다.
- **8월 24일, 브랜치 공유 사고.** 내 커밋이 옆 세션 브랜치에 얹혔고, 옮긴 뒤에는 반대로 옆 세션 커밋이 내 브랜치에 쌓였다. 커밋 직전에 브랜치를 읽는 규칙이 생겼다.
- **8월 26일, plan 번호 겹침.** 두 창이 같은 번호를 동시에 썼다. 번호 스크립트가 생겼다.
- **8월 27일, 커밋 섞임 두 번.** 파일을 지정해 add했는데도 옆 세션이 방금 고친 내용이 함께 잡혔다. 규칙만으로는 안 된다는 게 분명해졌다. 워크트리 격리가 기본이 됐다.
- **9월 8일, 훅 셋.** 규칙을 실행 자리로 옮겼다. 세션 브리핑, 공유 폴더 보호, 0건 규칙, 커밋 전 검사다. 같은 날 메모리도 파일 단위로 정리했다.

이 순서가 중요한 이유는, 하네스를 처음부터 다 만들려고 하면 무엇이 필요한지 모르기 때문이다. 사고가 나면 그 자리에 장치를 붙인다. 단 사고 뒤 규칙만 적고 끝내면 같은 사고가 또 난다. 규칙이 두 번 안 지켜지면 훅으로 옮긴다.

## 돌리면서 확인할 것

- 새 세션 첫 화면에 브리핑이 뜨나. 안 뜨면 훅이 안 걸린 것이다.
- 공유 폴더에서 `git add -A`를 시켜 본다. 막히면 보호 훅이 살아 있는 것이다.
- plan을 두 창에서 동시에 만들어 본다. 번호가 안 겹치면 스크립트가 미커밋까지 보는 것이다.
- 워크로그의 「남은 것」을 한 달에 한 번 다시 재서 닫는다. 막던 것이 사라져도 아무도 안 닫아 준다.
- 훅 파일이 작업 폴더마다 같은 판인지 확인한다. 훅도 낡는다. 메인 폴더의 훅이 두 세대 뒤처져 있어 재측이 안 된 일이 있다.
- 훅의 헛걸림은 실제 로그로 잰다. 목표(20% 아래)에 못 미치면 넓히지 않는다. 「0건」 훅은 48건에서 37.5%라 넓히지 않고 닫았다.
