# [20] 운영 0. 하네스

> 구분: 운영 · 영역: 공통

## 무엇을 돌리나

세션이 굴러가게 하는 장치입니다. 영역과 무관하게 공통입니다. 구축 편이 기준을 세운다면 하네스는 그 기준이 매일 지켜지게 만드는 장치입니다. 일곱입니다.

1. **워크로그.** 날짜별 파일 하나. 세션이 시작하면 오늘 것을 먼저 읽고, 끝날 때 무엇을 했고 무엇이 남았는지를 적습니다. 계획과 기록이 같은 파일에 있습니다. 워크로그가 없으면 다음 세션은 어제를 모릅니다.
2. **plan 문서와 번호 스크립트.** 진행 중인 일은 레포의 plan 폴더가 정본입니다. plan마다 첫 줄에 상태를 적습니다. 새 plan은 스크립트로 만듭니다. 번호를 손으로 고르면 겹칩니다. 옆 창이 만들어만 두고 커밋 안 한 파일은 git 이력에 없기 때문입니다. 스크립트는 원격 브랜치, 모든 워크트리, 미커밋 파일까지 훑습니다.
3. **워크트리 격리.** 커밋할 일이 있는 세션은 시작 때 작업 폴더를 따로 만듭니다. 세션 여럿이 한 폴더를 쓰면 커밋 소유가 흐려집니다. 충돌 보고를 받으면 이미 늦습니다.
4. **훅 셋.** 세션 시작 때 브리핑을 첫 화면에 얹는 훅(공유 폴더인지, 원격 브랜치보다 얼마나 뒤졌는지, 열린 체크박스가 몇 개인지, 오늘 워크로그가 있는지). 공유 폴더에서 위험한 git 명령을 실행 직전에 막는 훅. 「0건」 결과가 나오면 「범위를 적었나」를 상기시키는 훅. 커밋 직전에 문서 형식과 체인지셋을 검사하는 훅. 규칙으로 적어 두는 것만으로는 안 지켜져서 훅으로 옮겼습니다.
5. **메모리.** 사실 하나에 파일 하나. 사용자가 누구인가, 어떻게 일하라고 했는가, 무슨 결정이 있었는가, 어디를 보면 되는가. 색인 한 장이 세션마다 읽힙니다. 레포에 이미 있는 것은 적지 않습니다.
6. **토큰 절약.** 어디서 새는지 먼저 재고 도구를 붙입니다. 재 보니 셸 출력이 3할이었고, 그 뒤에 압축 도구를 넣었습니다.
7. **작업 화면(파세오).** 에이전트는 터미널 창이 아니라 파세오에서 띄웁니다. 레포마다 워크스페이스가 있고, 그 안에 대화가 한 줄씩 쌓여 상태 점으로 진행을 봅니다. 띄울 때는 프로필 셋 중에 고릅니다. 평소 작업, 깊이 생각할 일, 그리기와 코딩입니다. 에이전트마다 워크트리를 따로 만들 수 있어서 3번 격리와도 맞물립니다.

## 왜 이 자리가 필요한가

에이전트는 세션마다 초기화됩니다. 어제 무엇을 했는지, 어느 브랜치에 있는지, 옆 세션이 무엇을 고치고 있는지 모릅니다. 사람이 매번 말해 주면 되지만 그러면 사람이 하네스가 됩니다. 장치로 옮기면 사람은 판단만 하면 됩니다.

## 이렇게 된 이야기

하네스는 한 번에 설계된 게 아니라 사고마다 하나씩 붙었습니다. 순서대로 적습니다.

- **6월, 워크로그.** 실험 첫 주부터 날짜별로 썼습니다.
- **6월 17일, 파세오.** 에이전트를 파세오에서 띄우기 시작했습니다. 이후 모든 레포 작업이 여기서 돌았고, Prism 레포에서만 에이전트를 750개 넘게 띄웠습니다. 문제없이 돌아서 사고 기록이 없었고, 그래서 이 목록에 10월에야 올라왔습니다.
- **7월 13일, 단일 에이전트로.** 두 종류의 에이전트를 병행하다 하나로 줄였습니다. 병렬이 필요하면 별도 구독이 아니라 서브에이전트와 워크트리로 갑니다. 팬아웃은 서너 개가 기본입니다. 열 개를 띄웠다가 세션 한도에 걸린 날이 근거입니다.
- **8월 11일, 공유 폴더 사고.** `git add -A`로 옆 세션의 미커밋 작업이 내 커밋에 딸려 갔습니다. 규칙이 생겼습니다.
- **8월 24일, 브랜치 공유 사고.** 내 커밋이 옆 세션 브랜치에 얹혔고, 옮긴 뒤에는 반대로 옆 세션 커밋이 내 브랜치에 쌓였습니다. 커밋 직전에 브랜치를 읽는 규칙이 생겼습니다.
- **8월 26일, plan 번호 겹침.** 두 창이 같은 번호를 동시에 썼습니다. 번호 스크립트가 생겼습니다.
- **8월 27일, 커밋 섞임 두 번.** 파일을 지정해 add했는데도 옆 세션이 방금 고친 내용이 함께 잡혔습니다. 규칙만으로는 안 된다는 게 분명해졌습니다. 워크트리 격리가 기본이 됐습니다.
- **9월 8일, 훅 셋.** 규칙을 실행 자리로 옮겼습니다. 세션 브리핑, 공유 폴더 보호, 0건 규칙, 커밋 전 검사입니다. 같은 날 메모리도 파일 단위로 정리했습니다.

이 순서가 중요한 이유는, 하네스를 처음부터 다 만들려고 하면 무엇이 필요한지 모르기 때문입니다. 사고가 나면 그 자리에 장치를 붙입니다. 단 사고 뒤 규칙만 적고 끝내면 같은 사고가 또 납니다. 규칙이 두 번 안 지켜지면 훅으로 옮깁니다.

## 돌리면서 확인할 것

- 새 세션 첫 화면에 브리핑이 뜨나. 안 뜨면 훅이 안 걸린 것입니다.
- 공유 폴더에서 `git add -A`를 시켜 봅니다. 막히면 보호 훅이 살아 있는 것입니다.
- plan을 두 창에서 동시에 만들어 봅니다. 번호가 안 겹치면 스크립트가 미커밋까지 보는 것입니다.
- 워크로그의 「남은 것」을 한 달에 한 번 다시 재서 닫습니다. 막던 것이 사라져도 아무도 안 닫아 줍니다.
- 훅 파일이 작업 폴더마다 같은 판인지 확인합니다. 훅도 낡습니다. 메인 폴더의 훅이 두 세대 뒤처져 있어 재측이 안 된 일이 있습니다.
- 훅의 헛걸림은 실제 로그로 잽니다. 목표(20% 아래)에 못 미치면 넓히지 않습니다. 「0건」 훅은 48건에서 37.5%라 넓히지 않고 닫았습니다.
