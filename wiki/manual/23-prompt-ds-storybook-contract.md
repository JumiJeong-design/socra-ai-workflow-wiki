# [23] 프롬프트 3. DS → 스토리북 계약 정리

> 구분: 운영 · 영역: 프론트

## 언제 쓰나

DS의 계약·계약 제외·계약 불필요 섹션을 오가며 정리할 때, 그리고 DS와 코드가 다른 곳을 찾아 어느 쪽으로 통일할지 정할 때.

## 이렇게 시킨다

```text
[섹션 정리]
이 섹션들은 「스토리북에 올리는가」의 축이야. 계약 md가 있는지 없는지의 축이 아니야. 계약 제외에 있는 것도 계약 파일은 다 있어.
판정은 origin/main의 스토리 파일(*.stories.*)을 정확한 이름으로 대조해줘. 이름이 닮은 별개 컴포넌트가 오검색에 걸려.
미계약건 중에 계약건으로 올릴 것, 계약 제외·불필요 중에 올릴 것, 반대로 내릴 것을 전부 표로만 줘. 노드 · 현재 섹션 · 소비처 수(제품 인스턴스 · 패키지 내부 import · 스토리 파일) · 축과 슬롯과 텍스트 속성 유무 · 계약 md 유무 · 제안 섹션 · 계약의 스토리 요구사항 절 근거.
내릴 후보는 제품 인스턴스 0 · 패키지 소스 import 0 · 스토리 0 · 계약 요구 0, 넷을 다 실측한 것만 올려줘. 하나라도 있으면 표에 남겨 둬.
여기서 「정리」는 표까지야. 옮기는 건 내가 확정하면 그때 시킬게.
옮길 때는 목록(노드 id → 대상 섹션)을 먼저 표로 주고, 옮긴 뒤 대상 섹션과 원래 섹션의 자식 목록 전수 · 겹침 0 · 페이지 스크린샷을 같이 보고해줘. 띠 이름표 자체는 손대지 마.

[DS와 코드 대조]
코드 쪽은 origin/main에서 딴 워크트리에서 읽어줘. 시작할 때 git rev-list --left-right --count origin/main...HEAD를 보고에 적고, 왼쪽이 0이 아니면 이 트리의 계약·코드를 근거로 쓰지 마.
먼저 컴포넌트 드리프트와 토큰 드리프트 검사 스크립트를 돌려줘. 색은 이름 말고 hex와 램프 번호로 대조해줘. 회색 이름이 한 칸 밀려 있어서 이름으로 대조하면 오탐이 나.
물어보기 전에 셋을 걸러줘. ① 마스터 description · 계약 · plan에 이미 결정이 적혀 있는지 ② 화면 인스턴스가 override로 덮어서 실제로는 안 보이는 차이인지 ③ 일부러 다르게 둔 것(글래스 표면 같은)인지. 걸러진 건 정합 작업으로 처리하고 남은 것만 물어봐줘.
어느 쪽으로 통일할지는 나에게 꼭 물어봐줘. 「DS 수정 / 코드 수정 / 코드에 토큰 포팅」 셋 중 추천을 붙여서 물어봐줘. 원인이 「값이 틀렸다」인지 「코드에 칸이 없다」인지도 갈라줘.
물을 때 같이 붙일 것. 같은 상태를 쓰는 마스터 전수 분포표 · 대비값 · 영향 인스턴스 수.
시각물은 항목당 한 컷이야. 피그마 렌더와 코드 렌더를 같은 배율 원본 해상도로 나란히 놓고, 색은 hex를 옆에 적어줘. 캔버스에 만들지 말고 파일로 줘.

[게시와 수락]
마스터를 고친 뒤 게시·수락을 나한테 부탁하지 마. 값 변경이면 이미 놓인 인스턴스에 직접 넣어줘.
구조 변경이라 게시가 꼭 필요하면 「이 게시가 막아 주는 것」 한 줄과 소비 파일에서 키를 임포트해 본 결과를 같이 올려줘. 상태값만 보고 게시가 남았다고 하지 마.
```

## 왜 이 문장인가

- **「계약건」의 축을 한 줄로 박았다.** 섹션 이름이 「계약」이라 계약 파일 유무로 오해했다. 실제 축은 게시 여부다.
- **내릴 후보는 넷을 다 실측한 것만.** 이름이 닮은 별개 컴포넌트가 검색에 걸려 쓰고 있는 걸 「안 쓴다」로 판정한 일이 있었다.
- **정리는 표까지.** 옮기는 건 게시 구조를 바꾸는 일이라 사람이 확정한다.
- **코드는 origin/main 워크트리에서.** 뒤처진 트리의 「안 돼 있다」는 「아무도 안 했다」가 아니다.
- **색은 이름 말고 값으로.** 피그마와 코드의 회색 이름이 한 칸 밀려 있어 같은 사고가 두 번 났다.
- **묻기 전에 셋을 거른다.** 이미 결정된 것, override로 가려진 것, 일부러 다른 것을 같이 올리면 사람이 같은 판단을 반복한다.
- **게시·수락을 부탁하지 않는다.** 값 변경은 인스턴스에 직접 넣으면 된다. 수락도 만능이 아니다. 프록시 세트가 여러 벌 살면 수락해도 안 바뀐다.

## 결과를 이렇게 확인한다

- 표에 소비처 수 세 칸이 다 채워져 있나.
- 통일 질문에 추천과 원인 구분이 붙어 있나. 없으면 되돌린다.
- 시각물이 같은 배율인가. 축소한 렌더로 색을 판정하면 틀린다.
