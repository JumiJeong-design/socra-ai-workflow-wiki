# [27] 부록. 바로 붙여 넣는 지시어

> 구분: 운영 · 영역: 공통

## 언제 쓰나

21~26장의 프롬프트를 상황별로 한 장에 모은 빠른 판이다. 왼쪽 칸에서 상황을 찾고 오른쪽 문장을 그대로 복사해서 쓴다. 범위와 확인 방법까지 필요하면 해당 장으로 간다.

## 이렇게 시킨다

### 하루 흐름

| 언제 | 붙여 넣을 말 |
|---|---|
| 시작할 때 | 오늘 해야 할 일 남은거 시작하자. |
| 일을 나눌 때 | 병렬로 일 시킬수 있도록 업무 구분하고 각 에이전트에게 보낼 프롬프트 만들어줘. |
| 맥락이 기억 안 날 때 (다음 날로 이어졌거나 헷갈릴 때) | 너가 처음에 하던일은 뭐고, 종료한건 뭐고, 그래서 할일이 뭔지로나눠서 얘기해봐 / 어 그럼 너한테 처음에 시킨일은 뭐고 이제 뭐남은거야? |
| 이해가 안 될 때 | 더 쉽게 말해주고 시각물로 판단하고 비교할수있게 보여줘 |
| 마무리할 때 (다른 이슈가 생겼을 때) | 처음에 너한테 말한 할 일 다 했으면 워크로그 남기고 종료하고, 다른 할 일이 있으면 다른 에이전트가 이어서하는게 나을지 너가 마무리하는게 나을지 판단해서 말해줘 |
| 다 했는지 확인할 때 | 응 처음에 내가 요구한건 다 한거지? 워크로그 올리고 피그마 수정하고, 스토리북이랑 git 코드 정합하고, 잘 올라간거 재검토하고, 푸시하고 커밋하고 머지하고 배포하고, 너 할일 다 한거 맞지? |

### 디자인 시스템 점검

| 무엇을 | 붙여 넣을 말 |
|---|---|
| DS 안 토큰 점검 | 디자인 시스템 내부에 토큰이 잘 정합되어있는지 검토해줘. 특히 컴포넌트를 전수하면서, 변수나 스타일이 미바인딩된 색, 텍스트 스타일, 라운드, 두께 등 하드코딩 케이스가 있는지 주의해서 검토해줘. |
| 화면 → DS | 디자인 화면에서 반복적으로 등장하는 케이스가 있다면(컴포넌트화 가능한 요소가 있다면) 컴포넌트화 해서 DS에 생성 후 디자인 화면에 대치해줘. |
| 화면의 토큰 점검 | 디자인 화면에서 토큰값 안쓴 케이스가 있는지 검토하고 변경해줘. 만약 안쓴케이스가 컴포넌트면 DS에 있는 컴포넌트를 수정해줘. |
| DS → 스토리북 | DS에서 Story book 미계약건을 계약건에 올릴만한게 있으면 검토해줘. 계약 제외나 계약 불필요에 있는 항목중에 컴포넌트로 올릴만한게 있는지 살펴봐줘. 또는 피그마 계약 쪽에 위치한 컴포넌트중에서 계약 제외나 불필요에 넘길만한 요소가 있는지도 살펴보고 정리해줘. 다 끝내면 스토리북에 올라간 항목에 맞게 피그마내에서 위치 조정 해줘. |
| DS ↔ 코드 | DS와 코드가 다른 부분이 있는지 살펴보고 DS 혹은 코드로 일치시키는 작업을 진행해줘. 대신 어느쪽으로 통일할지는 나에게 꼭 물어봐줘. 알려줄때는 시각물을 함께 보여줘. |
| 배포 | 해당 작업 끝나면, 코드 충돌나지 않도록 PR 올리고 머지하는 작업 진행해줘. 그리고 확정된 건에 대해서 npm 배포하고싶어. |
