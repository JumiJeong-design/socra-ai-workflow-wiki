# [25] 프롬프트 5. 세션 시작 · 병렬 분배 · 맥락 복구 · 마무리

> 구분: 운영 · 영역: 공통

## 언제 쓰나

오늘 할 일을 시작하거나, 에이전트 여럿에 나누거나, 어제 맥락을 잃었거나, 끝낼지 넘길지 정할 때. 영역과 무관하게 매 세션 쓴다.

## 이렇게 시킨다

### 세션 시작할 때 (제일 먼저 붙이는 문구)

```text
커밋할 일이 생길 작업이면 시작 전에 작업 폴더(worktree) 만드는 스크립트로 책상부터 나누고 거기서 해줘. 다 하고 나서 나누면 늦어.
오늘 worklog(오늘 날짜 원문)를 먼저 읽고 시작해줘. 새 컴포넌트를 만들기 직전과 커밋 직전에 그날 「설계 결정」과 「함정」을 다시 읽어줘.
「남은 일」은 지금 폴더에서 세지 말고 origin/main의 docs/plans와 worklog 원문에서 세줘. 목록 옆에 git rev-list --count HEAD..origin/main 값을 적어줘.
착수 전에 항목마다 「이미 됐나」를 같이 봐줘. git log --oneline -10 origin/main -- <손댈 파일>, 최근 머지된 PR, 이름이 겹치는 worktree 셋.
```

### 언제나 지키는 것

```text
파일은 둘이야. DS 파일과 제품 파일. 이름은 바뀌니까 파일 키로 찾아줘.
「없다 · 0건 · 근거 없음」을 적을 때는 어디를 봤는지 같은 줄에 적어줘. DS 파일만인지, 제품 파일 컷까지 봤는지, 이름 말고 모양으로도 찾았는지. 못 적으면 안 찾은 거야.
범위를 좁혀서 잰 수치는 좁힌 조건을 수치 옆에 적어줘. 「13곳」 말고 「chat/report의 solid+enabled 30개 중 13곳」처럼.
이 프로젝트에서 처음 해 보는 유형이면 착수·완료 보고에 표시해줘. 내가 거기부터 볼게.
다크 모드는 이번 범위에 넣을지 말지 내가 말할게. 안 물어봤으면 라이트만 봐줘.
```

### 병렬로 나눌 때

```text
오늘 해야 할 일 남은 거 시작하자. 한 번에 하나씩 가져와줘. 여러 건을 한꺼번에 나열하면 오판이 묻혀.
병렬로 시킬 수 있게 업무를 나누고 각 에이전트에게 보낼 프롬프트를 만들어줘. 3~4개까지만.
프롬프트마다 넣을 것. ① 첫 줄에 작업 폴더 스크립트로 시작 ② 손댈 파일과 건드리지 말 파일(공유 plan · 오늘 worklog) ③ 서버 포트 번호 ④ 완료 보고는 PR 번호로 ⑤ 참조할 정본 버전.
업무는 같은 파일을 둘이 안 고치게 파일 단위로 나눠줘. 피그마 감사는 페이지 통째 덤프 말고 컴포넌트 단위 스크립트로 쪼개줘.
```

### 맥락이 기억 안 날 때

```text
처음에 하던 일은 뭐고, 종료한 건 뭐고, 그래서 할 일이 뭔지로 나눠서 얘기해줘.
종료한 건 항목마다 origin/main에서 무엇으로 확인했는지(PR 번호 · grep한 문자열)를 붙여줘. 로컬 기억으로 답하지 마.
할 일은 origin/main과 오늘 worklog로 다시 재서 말해줘.
git status -sb 첫 줄과 gh pr list --head <브랜치> 결과도 같이 말해줘. 브랜치가 이미 지워졌거나 충돌 중일 수 있어.
```

### 마무리할 때

```text
처음에 말한 할 일 다 했으면 워크로그 남기고 종료해줘.
워크로그는 쓰자마자 바로 커밋해줘. 커밋 직전에 git diff --cached --stat으로 내 몫만인지 봐줘. 자정 넘겼어도 그날 날짜 파일을 만들어줘. 계획은 「미해결 항목」 절에 넣고 「오늘 완료」 목록은 따로 만들지 마.
종료할 때 공유 폴더는 fetch만 해줘. reset --hard나 checkout main 하지 마. 내 worktree만 치워줘.
다른 할 일이 있으면 다른 에이전트가 이어서 하는 게 나을지 네가 마무리하는 게 나을지 판단해서 말해줘. 조사 비용이 편집량보다 크면 네가 마무리해줘.
넘긴다면 브랜치 · worktree 경로 · 미푸시 커밋 · PR 번호와 상태 · 하면 안 되는 것과 그 조건이 언제 풀리는지를 워크로그 미해결 항목에 적어줘.
```

## 왜 이 문장인가

- **책상 나누기가 첫 프롬프트다.** 원래 배포 절 뒤에 있던 것을 앞으로 끌어올렸다. 다 하고 나서 나누면 커밋이 섞인다. 8월 27일에 두 번 났다.
- **남은 일은 origin/main으로 센다.** 공유 폴더는 백 커밋씩 뒤처져 있어서, 여기서 세면 이미 끝난 일이 남은 일로 보인다.
- **「이미 됐나」를 먼저 본다.** 「A 때문에 대기」는 A가 사라져도 아무도 안 닫는다. 하루에 열린 항목 36건이 이미 끝나 있었다.
- **0건에는 범위를 같이.** 0은 검산할 대상이 없다. 없는 게 아니라 안 본 것일 수 있다. 훅으로도 상기시킨다.
- **처음 하는 유형은 표시한다.** 검수는 유량이다([원리 1](#manual-31)). 어느 자리에 집중할지 사람이 알아야 한다.
- **팬아웃은 3~4개.** 열 개를 띄웠다가 세션 한도에 걸렸다. 파일 단위로 나누지 않으면 같은 파일을 둘이 고친다.
- **맥락은 로컬 기억이 아니라 origin/main으로.** 뒤처진 트리의 기억은 틀린다.
- **워크로그는 바로 커밋, 공유 폴더는 fetch만.** `reset --hard`와 `checkout main`은 훅이 막지만 프롬프트에도 적어 둔다.
- **넘길지 마무리할지는 조사 비용으로.** 다음 에이전트가 맥락을 다시 쌓는 비용이 편집량보다 크면 이어서 한다.
